# Автономный сбор и разовая синхронизация в SQLite

Кольцо измеряет и накапливает историю без ноутбука. Постоянное BLE-соединение,
онлайн-пульс и daemon для этого сценария не запускаются. Полноту автономной
записи сна после первого сброса ещё нужно проверить на ночной выгрузке.

## Утренняя синхронизация

Из корня проекта в PowerShell:

```powershell
.\ringlink\native_ble.ps1 sync
```

Для этого кольцо должно быть рядом с включённым ноутбуком. Если его сложно
найти при ношении, ненадолго положить на зарядную подставку. Oura на iPhone
не переподключать. Интернет для синхронизации не требуется.

Порядок работы:

1. Проверить зависимости, доступ к БД и отсутствие другого sync/daemon/probe.
2. Найти кольцо и пройти авторизацию локальным ключом.
3. Получить батарею и историю с последнего курсора с перекрытием на один час.
   При пустой выгрузке за устаревшим курсором один раз запросить историю с начала.
4. Записать кадры в events.jsonl, выполнить flush/fsync, сохранить курсор
   и только затем подтвердить кольцу получение порции.
5. Синхронизировать часы и закрыть BLE-соединение.
6. Декодировать данные, сохранить оригиналы и события в SQLite транзакцией.
7. Обновить таблицы дашборда через существующий OuraParser и записать статус.

Запуск без аргумента у native_ble.ps1 также выполняет sync. Никакой
периодический запуск или задание планировщика этим не устанавливается.
Кнопка Sync now в backend при наличии нового .venv выбирает offline_sync.py.

## Где находятся данные

Рабочая БД дашборда на Windows:

```text
%APPDATA%\CrackedOura\oura_database.db
```

Дополнительные таблицы:

| Таблица | Назначение |
| --- | --- |
| ring_raw_frames | Оригинальные BLE-кадры и время их получения |
| ring_events | Декодированные события, исходные payload, время UTC и источник оценки времени |
| ring_imports | Количество добавленных кадров/событий при каждом импорте |

Декодированное событие определяется поколением загрузки, типом, счётчиком
кольца и исходным payload. Повторная выгрузка с перекрытием не создаёт
копий событий. Оригинальные приёмы одного кадра в разные моменты могут
храниться отдельно: это журнал транспорта, а не дополнительные измерения.
При повторном импорте одного файла также не дублируются сырые кадры.

Для уже сохранённых событий UTC-время остаётся стабильным, чтобы очередной
импорт не размножал точки дашборда из-за небольшого сдвига временной привязки.
Источник времени хранится рядом; будущую коррекцию часов можно сделать явно
из оригиналов. Текущий декодер поколений загрузки рассчитан на сохранение
полной последовательности events.jsonl; offline_sync не ротирует этот файл.

Таблицы дашборда: heart_rate, temperature, ring_battery, activity, sleep,
sleep_session, readiness. Отсутствующие показатели не подменяются данными:
до первой ночной записи таблицы сна пусты. Оценки стадий/баллов, когда они
появятся, остаются приближениями алгоритмов проекта. В таблице temperature
сохранена существующая конвенция проекта — температура кожи в Fahrenheit;
в ring_events исходные декодированные температуры остаются в Celsius.

## Повтор обработки без кольца

```powershell
.\ringlink\native_ble.ps1 import
```

Если BLE-выгрузка завершилась, но обработка дала ошибку, сохранённые кадры
можно импортировать заново без подключения. Транзакция оригиналов/событий
атомарна; импорт таблиц дашборда использует upsert по существующим ключам.
Если обработка дашборда прервётся между таблицами, повторный import завершит её.

Для тестовой/переносной БД можно задать CRACKED_OURA_DATA_DIR. Обычный запуск
использует AppData. БД, ключи, файлы событий и экспорты в Git не отправляются.

Проверено: полный цикл с реальным кольцом, повторный импорт того же файла
с нулём новых событий и неизменным количеством точек, изолированный тест
импорта синтетического пульса/температуры в БД дашборда и откат при повреждённом JSON.
