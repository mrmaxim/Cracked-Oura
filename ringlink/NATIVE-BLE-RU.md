# Ring 4: встроенный Bluetooth и собственный ключ

Экспериментальная поддержка Windows через Bleak. Проверены приём BLE-рекламы
адаптером Intel и 13 тестов без оборудования. Сопряжение с реальным Ring 4
и длительная синхронизация пока не подтверждены.

## До сброса

Из корня репозитория, PowerShell (Python 3.12+):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ringlink/requirements-native.txt
.\ringlink\native_ble.ps1 scan
```

`scan` принимает рекламные пакеты, не подключаясь к кольцу. Синхронизируйте
кольцо с Oura на iPhone и выполните Settings → Back up all data. Затем закройте
Oura, выключите Bluetooth через **Настройки iPhone**, положите кольцо на зарядку
рядом с ноутбуком и повторите scan. Наличие в списке ещё не доказывает, что
Windows сможет выполнить сопряжение и авторизацию.

Остановите фоновые клиенты кольца, включая старый watchdog. До готовности
клиента кольцо не сбрасывайте.

## Сброс и первое подключение

Сброс удаляет данные с кольца; синхронизированная с аккаунтом история сохраняется.
Выполните резервное копирование и сброс по
[официальной инструкции Oura](https://support.ouraring.com/hc/en-us/articles/360025446854-Factory-Reset-an-Oura-Product).
Для сброса из приложения Bluetooth iPhone потребуется включить обратно.
После завершения не нажимайте Continue / повторное подключение: закройте
Oura, забудьте кольцо в настройках Bluetooth iPhone и выключите Bluetooth.
Если телефон успеет подключиться первым, сброс может потребоваться повторить.

В исходном проекте наблюдалось, что Ring 4 принимает новый ключ только при
первом подключении после завершённого сброса. Это наблюдение на прошивке
автора, а не гарантия для всех версий. Поэтому между сбросом и pair нельзя
выполнять battery, verify или подключаться через настройки Windows либо
BLE-обозреватель. Поиск без подключения допустим. Ключ, установленный до
завершения сброса, может быть стёрт самим сбросом.

Положите кольцо на зарядку рядом с ноутбуком и выполните:

```powershell
.\ringlink\native_ble.ps1 pair -FactoryResetDone
```

При необходимости подтвердите системное окно Bluetooth-сопряжения Windows.
Команда не сбрасывает кольцо: она сохраняет новый ключ до первого подключения,
устанавливает его, проверяет авторизацию, синхронизирует время и переподключается.
Проверка успеха требует, чтобы на новом соединении батарея была закрыта без
авторизации, а после авторизации сохранённым ключом стала доступна.

Новый ключ находится **вне OneDrive и Git**:

```text
%LOCALAPPDATA%\CrackedOura\ringlink\oura_key.hex
```

Не отправляйте содержимое ключа в чат. BLE bond хранит Windows; ключи
`ring_bond.json` от Nordic-донгла для этого подключения не используются.

## Восстановление после ошибки

Ключ сохраняется даже при ошибке установки: кольцо могло принять его, а ответ
потеряться. Не удаляйте файл и не генерируйте новый автоматически. Сначала:

```powershell
.\ringlink\native_ble.ps1 verify
```

Повторный pair откажется перезаписывать файл. Новый сброс и перенос старого
ключа в отдельную локальную резервную копию выполняются осознанно, после
разбора причины ошибки. Устаревшее сопряжение Windows может потребовать
удаления конкретного кольца в «Параметры → Bluetooth и устройства».

## После сопряжения

```powershell
.\ringlink\native_ble.ps1 battery
.\ringlink\native_ble.ps1 events
```

История сохраняется в существующий формат `ringlink/events.jsonl`. Сразу
после сброса данных мало. Нужно отдельно проверить включение режимов HR/SpO2
и появление записей после ношения: авторизация не гарантирует, что все
измерения уже включены.

Daemon и one-shot sync поддерживают `OURA_TRANSPORT=native`. Команда
`native_ble.ps1 daemon` запускает daemon в переднем плане; Ctrl+C останавливает.
Для обработки данных и панели нужны зависимости backend и его настройка;
одного requirements-native.txt недостаточно. Старый watchdog использует
venv310 и автоматически на это окружение не переключается. До проверки
сопряжения daemon не запускайте.
